# Supabase 建表：复制执行说明

你负责创建云项目和在控制台执行 SQL；SQL 已写好，不需要自己设计表。

## 1. 创建表

1. 登录 Supabase，打开你的 MVP 项目。
2. 左侧打开 **SQL Editor（SQL 编辑器）**，新建查询。
3. 打开本目录 `001_schema.sql`，复制**全部内容**粘贴；使用项目的 `postgres` 数据库角色执行。
4. 点击 Run。成功后继续下一步；如果报错，保留报错信息交给 Codex，不手动删表重试。
5. 新建查询，复制执行 `002_verify.sql`。应显示 19 张表、版本 `001`，三个外部 API 角色的权限结果均为 false。

表建在 **dialogue schema**（可以理解为数据库内的业务文件夹），在表浏览器切换到 dialogue 才能看到。不要把 dialogue 添加到 API 的 Exposed schemas；业务通过后端访问，浏览器不直接访问表。

`001_schema.sql` 是首次安装脚本，包含事务：失败会整体回滚；成功后再次执行会提示 schema 已存在，不会静默清空或重建数据。后续变更使用编号增量脚本，不通过重复运行初始脚本升级。

## 2. 配置后端账号

`003_runtime_role.sql.example` 是可选的后端运行账号模板。使用前替换密码占位值；不能直接带着占位密码执行。它仅授权业务表读写，不授予建表或删除表权限；账号仅供可信后端使用，不能放到前端。

日常后端连接使用此账号；迁移继续使用具有建表权限的管理连接。连接方式与 pooler 用户名格式必须按项目实际入口核对，不能只改用户名后假设连接可用。当前 M1 尚未实现数据库连接，执行这些 SQL 不会自动让页面就绪检查变成 200，后续仍需完成 M2 代码。

## 3. 已包含什么

剧集、视频版本、对象资产、许可、字幕轨、原始字幕、字幕版本、双语台词、对齐关系、逻辑片段、片段台词、实体导出关系、分享、任务、管理员、会话、审计、结构版本，共 19 张表。

包含主键、外键、唯一约束、毫秒时间约束、60 秒片段上限、跨版本/字幕版本关联约束、搜索与任务索引、RLS 与默认权限限制。视频仍放 R2，数据库不保存 MP4。

应用仍须校验：素材许可有效期与地域、片段不超过视频时长、连续选句、已发布内容不可原地修改。SQL 建表不是这些业务功能已经实现。

## 4. 验证范围与后续迁移

这些脚本尚未在你的 Supabase 项目实际运行，不代表云端建库已经完成。不自动连接你的账号，也不执行删除脚本。

手动 SQL 与后续 Alembic 必须使用同一结构版本：M2 实现时识别 `dialogue.schema_versions` 的 `001`，核验实际表结构后再建立 Alembic 基线；不能对已经手动建表的数据库再次运行同一批 CREATE TABLE。数据库有数据后，任何回退先备份，再写定向逆向迁移；本目录不提供一键删库命令。

参考：[Supabase 自定义 schema](https://supabase.com/docs/guides/api/using-custom-schemas)、[数据库角色](https://supabase.com/docs/guides/database/postgres/roles)。
