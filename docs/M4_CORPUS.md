## 你从哪里抽查

启动前后端后打开 **http://127.0.0.1:5173/review**。这是独立本地审核页面，首页不展示内部诊断信息。

1. 等视频元信息加载完成，再点击“20 个分散抽查点”中的时间按钮。
2. 每次会从台词前约 0.7 秒播放，片段后约 0.8 秒暂停。
3. 核对听到的英文、中文意思与字幕出现时间。初始参考目标偏差不超过约 300ms。
4. 优先查看“待关注片段”；缺少英文的画面文字、同时出现的中文特效文字不一定是数据错误。
5. 把问题时间点和描述发给 Codex，例如“10:30 附近字幕提前 1 秒”。不需要你手动编辑数据库。

链接约一小时有效，失效时点击“刷新视频链接”；刷新会重置当前选区。该页面仅在 development 且回环地址访问时开放，不是公开管理员后台，不能直接部署公网。

## 导入、纠错与确认

在项目根目录执行以下目录切换，然后运行命令：

```powershell
cd services/backend
../../.venv/Scripts/python.exe -m app.corpus_cli import --version d48b2a8c-b61b-4813-955d-bafc473efb5c
```

如果整个字幕需要延后 1 秒：

```powershell
../../.venv/Scripts/python.exe -m app.corpus_cli import --version d48b2a8c-b61b-4813-955d-bafc473efb5c --offset-ms 1000
```

时间映射为 `视频时间 = 字幕时间 × scale + offset_ms`；`--scale` 默认 1。只有抽查确认存在漂移时才修改。不同参数创建新 revision，保留原始 cue。分段非线性偏移不自动推断，使用逐条纠错或换匹配视频。

逐条纠错文件使用 UTF-8 JSON，示例：

```json
[
  {"language": "zh", "seq": 1, "text": "修正后的中文"},
  {"language": "en", "seq": 2, "start_ms": 4960, "end_ms": 6530}
]
```

通过 `--corrections 文件路径` 导入；language 和 seq 对应原字幕轨，未出现的条目保持原样。纠错只影响新 revision 的 segment，原 cue 不覆盖。实际纠错内容应由 Codex 根据你的反馈生成，不直接套用示例内容。

本轮修订已在收到用户“审核未发现问题”的反馈后执行审核确认，当前无需重复运行。之后如新建了修订版本，应再次人工抽查，并仅对该次确认过的新 revision 执行：

```powershell
../../.venv/Scripts/python.exe -m app.corpus_cli approve --version <视频版本ID> --revision <已复查的新字幕修订ID> --confirm-reviewed
```

如已创建纠错 revision，必须替换为最新确认的 revision ID。此操作记录审核审计并设置活动字幕版本；不授予公开素材权限，视频仍不会自动公开发布。
